Deployments with previews and instant rollback

Drag a folder onto the dashboard, run chroma deploy, or click Deploy in the playground. Pyre shaders compile during the build; a failing shader fails the build and production stays as it was. Clean URLs, custom 404 pages, SPA mode and <project>.your-domain hosting are built in.

  • Content-addressed storage: unchanged files cost nothing to redeploy
  • Every deployed file runs in a sandboxed origin, isolated from your account
  • Promote any READY deployment; the last 30 are kept

A realtime database, no setup

Each project gets JSON document collections stored in SQLite. Rules decide what your deployed pages may do: public reads for leaderboards and galleries, create-only writes for forms and guestbooks, or owner-only for anything private (use your API token from servers and CI). Subscribe to a collection and changes arrive instantly.

Server functions in Pyre or JavaScript

        
Pyre functions run @kernel programs on the server's CPU: numeric work like simulations or signal processing, always on. JavaScript functions are ordinary request handlers with access to your project's database; each request runs in a fresh process under Node's permission model (no filesystem, no subprocesses, no network), with code generation disabled, a string-only bridge to the host and time and memory limits. Administrators can turn JS functions off with ALLOW_JS_FUNCTIONS=0.

Analytics that update while you watch

        
Page views are counted on the server, so there is no tracking script to add or block. Visitors are identified by an HMAC of IP, user agent and project with a salt that rotates daily, so no cookies or raw IPs are stored. The dashboard streams every request live: visitors right now, traffic over time, top pages, referrers, devices, status codes, function calls and your own custom events.
