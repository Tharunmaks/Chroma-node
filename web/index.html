Pyre language

GPU code that reads like Python.

Pyre is a typed shader & compute language with indentation, type inference and friendly errors. One file compiles to GLSL for WebGL2, WGSL for WebGPU and JavaScript for Node — and the output matches pixel for pixel.

  • Types inferred, ints promoted to floats automatically
  • @fragment shaders and @kernel compute in the same language
  • Standard library: noise, fbm, SDFs, palettes, rotations
  • Errors point at the column and suggest the fix

Helix engine

        
A 3D engine where materials are code.

        
Helix wraps Three.js with the parts you actually want: live Pyre materials, glTF loading, bloom, orbit controls, auto-resize, and render-only-when-visible. Your deployed sites can import it directly.

        

          
scene.js


import { Helix, Models } from 'helix';

const engine = new Helix(canvas, { bloom: true });
const lava = engine.material(await fetch('lava.pyre').then(r => r.text()));
engine.add(engine.mesh(Models.torusKnot(), lava));
engine.add(await engine.load('robot.glb'));
engine.start();

Pyre Functions

        
GPU-style kernels, served over HTTP.

        
Put a @kernel in api/ and it becomes an endpoint. Each call runs in an isolated worker with a time limit, a memory cap and a loop budget, so untrusted code can't take the server down.

      

      

        
api/saxpy.pyre → POST /api/fn/my-site/saxpy


# api/saxpy.pyre
uniform a: float
buffer x: [float]
buffer y: [float]

@kernel(64)
fn saxpy(id: int):
    y[id] = a * x[id] + y[id]

$ curl -X POST localhost:3000/api/fn/my-site/saxpy \
    -H 'content-type: application/json' \
    -d '{"uniforms":{"a":2},"buffers":{"x":[1,2,3],"y":[10,10,10]}}'
{ "buffers": { "x": [1,2,3], "y": [12,14,16] }, "ms": 0.4 }

Security

        
Secure by default, not by checklist.

        
Chroma runs untrusted sites and untrusted GPU code next to your account. Every layer below is on out of the box and covered by tests.

      

      

        
scrypt passwords
Salted scrypt hashes, constant-time checks, account lockout after repeated failures and per-IP rate limits.

        
Sandboxed deployments
Every deployed file is served with a CSP sandbox, giving it an opaque origin: user sites can't read your session or call your API.

        
Strict CSP everywhere
No inline scripts except hashed import maps, frame-ancestors 'none', HSTS, COOP and nosniff on every page.

        
Isolated functions
Kernels run in fresh worker threads with wall-clock timeouts, memory limits, bounds-checked buffers and a loop budget.

        
CSRF & session safety
HttpOnly, SameSite=Strict cookies, per-session CSRF tokens, Origin checks; only hashes of sessions and API tokens are stored.

        
Hardened uploads
Path traversal, hidden files, control characters and oversized uploads are rejected; everything is audited per account.
